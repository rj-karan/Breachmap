# M1 — Lab + answer key + offline IAM evaluator

Due: 2026-11-24

## Goal

Make accuracy measurable before any collector exists. Ship the seeded lab as
JSON fixtures with a known-answer key, the Terraform that builds the AWS part
of it, and an offline AWS policy evaluator that is tested rule-by-rule from
the AWS documentation.

## Scope

- Python project scaffold: `uv`, `ruff`, `mypy --strict`, `pytest` + coverage,
  hardened CI, Dependabot.
- Lab answer key: a schema for "these paths must exist" and "these look open
  but must not be reported", plus the first seeded fixture set for the v1
  path family.
- Policy document model and matching: actions, resources, ARN wildcards,
  `NotAction` / `NotResource` / `NotPrincipal`, policy variables, condition
  operators and set operators.
- Evaluation logic: explicit deny, SCP, resource policy, permission boundary,
  session policy, identity policy, same-account versus cross-account, in AWS
  order. Limited to the five v1 actions.
- `sts:AssumeRoleWithWebIdentity` trust evaluation with GitHub OIDC `sub` and
  `aud` conditions (the Tinder case), and `sts:AssumeRole` role chaining.
- Terraform lab for AWS (OIDC provider, roles, bucket, secret, KMS key,
  budget alarm, `breachmap-lab=true` tags), kind config, lab GitHub
  workflows.
- Mutation harness on the seeded fixtures: change one thing, assert the
  evaluator decision changes exactly as the answer key predicts.
- `docs/learning-path.md` updated.

## Exit test

```
uv run pytest tests/lab tests/iam -q
terraform -chdir=lab/aws validate && terraform -chdir=lab/aws plan
```

Both pass. Every fixture in `lab/fixtures/` loads under its schema. Every
expected-allow and expected-deny in the answer key is reproduced by the
offline evaluator. `terraform apply` in the lab account is a manual step
documented in `lab/README.md`; `plan` must succeed offline.
