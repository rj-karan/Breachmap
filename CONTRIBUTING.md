# Contributing

Breachmap is run like a small team project even though it currently has one
maintainer. The process below is the process; it is not optional for the
maintainer either.

## Setup

```
uv sync --all-groups
uv run pre-commit install   # optional, mirrors CI
```

Python 3.12 is required. `uv python install 3.12` gets it.

## Workflow

1. Pick an issue (or open one using the task template). Every change traces
   back to an issue.
2. Move it to **In Progress** on the project board.
3. Branch from `main`: `type/N-slug`, for example `feat/12-trust-policy-sub`.
   `type` is one of `feat`, `fix`, `docs`, `chore`, `test`, `ci`, `refactor`.
4. Commit small and often with Conventional Commits, each ending in `Refs #N`:
   `feat(iam): evaluate StringLike on sub claim\n\nRefs #12`.
5. Run `uv run ruff check .`, `uv run ruff format --check .`, `uv run mypy`
   and `uv run pytest` before every push.
6. Open a PR with the template. The body must contain `Closes #N`.
7. Wait for CI. Squash-merge. The branch is deleted automatically.
8. `git checkout main && git pull`.

Nobody pushes to `main` directly, including the maintainer. Branch protection
enforces it.

## Code rules

- Type hints everywhere; `mypy --strict` must pass.
- Every IAM evaluation rule is a test first, quoting the AWS documentation
  sentence it implements, then the code.
- No graph edge without evidence metadata. The models refuse it.
- No cloud write permissions, ever. If a change needs one, the design is wrong.
- Fixtures are the source of truth for accuracy. A false positive or a miss
  becomes a fixture before it becomes a fix.

## Commit and PR hygiene

- No AI attribution trailers or "generated by" lines anywhere.
- Keep PRs under roughly 400 changed lines where possible.
- Docs change in the same PR as the code they describe.

## Learning
